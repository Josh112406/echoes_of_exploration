# Twelve-Hour Execution Plan

## Planning assumption

Six people start with no code or production assets. The goal is a complete hackathon product, not commercial polish: nine short encounters built from three reusable mechanic families, a 30-group catalog target, policies, accessibility routes, and a deployable static site.

## Hard rules

- All nine encounters must share stable templates.
- Feature/content freeze begins at Hour 4.
- Member 2 integrates continuously; no final-hour “big merge.”
- Sources, asset rights, accessibility, privacy, and complete campaign flow are never optional.
- Cut decorative motion, audio variety, Deep Dive length, then nonfeatured catalog breadth—never trust or safety requirements.

## Hour-by-hour plan

### Hour 0–1 — Foundation and contracts

**Whole team:** confirm challenge resources, roster, definition of done, repository, status board.

- M1: freeze product copy outline, campaign beats, submission fields.
- M2: create application shell, routing, build/deploy, schemas, validation, branch protections.
- M3: specify mechanic interfaces and build the reusable encounter shell.
- M4: create claim/source/asset ledgers; confirm nine primary sources and challenge-provided data.
- M5: freeze palette, type, responsive composition, reusable destination backgrounds, asset specs.
- M6: add semantic structure, settings shell, test matrix, policy-page skeletons.

**Gate:** title → observatory → placeholder encounter → result → catalog route works locally.

### Hour 1–2 — Vertical slice

Use Surveyor 1 as the end-to-end reference.

- M1: final opening and Surveyor story beats.
- M2: persistence, content loader, error boundary, first deploy preview.
- M3: first navigate/manage interaction with keyboard/touch.
- M4: Surveyor record, claim ledger, source panel, authentic image provenance.
- M5: observatory frame, Moon background, Surveyor sprite/illustration, authentic-media presentation.
- M6: keyboard path, screen-reader alternative, reduced motion, result/policy checks.

**Gate:** one polished encounter meets full acceptance criteria. Freeze mechanic/content contracts.

### Hour 2–4 — Parallel population

- M1: complete chapter transitions, ending, rewards, concise copy review.
- M2: map/catalog/search/filter/save/export/import/reset; prepare chapter lazy loading.
- M3: finish observe/infer and communicate/preserve families; configure all nine encounter skeletons.
- M4: populate nine featured records, sources, simplification notes, and initial catalog skeleton.
- M5: create reusable Moon/Mars/Elsewhere scenes, nine hero assets, patch system, optimize media.
- M6: accessible encounter alternatives, settings, audio framework, privacy/legal/accessibility drafts.

**Hour 4 gate:** all nine routes load valid content; feature and schema freeze.

### Hour 4–7 — Complete the campaign

- M1 pairs with M4 on narrative/science review.
- M2 integrates and fixes shared contracts only.
- M3 completes each encounter’s feedback, assistance, and result state.
- M4 expands catalog toward 30 groups; prioritizes sources over prose depth.
- M5 adds restrained motion and chapter identity; no unique cinematics.
- M6 tests every merged route and logs severity with reproduction steps.

**Gate:** beginning-to-end campaign completes; free exploration works; no unreachable mission.

### Hour 7–9 — Product completion

- Resolve critical/major defects.
- Finish catalog filters, policies, credits, sources, assistant disclosure, license notices.
- Verify authentic-versus-illustration labels.
- Test save migration, corrupt import, reset, unsupported graphics, lost focus, and low-effects mode.
- Audit initial bundle and chapter loads.

**Hour 9 gate:** release candidate. No enhancements.

### Hour 9–10 — Cross-device and accessibility pass

- Desktop Chrome/Firefox/Edge and one Safari path if available.
- Mobile viewport and real touch device if available.
- Keyboard-only completion.
- Screen-reader smoke test of title, map alternative, one encounter alternative, catalog, settings, policies.
- Contrast, zoom, reduced motion, muted audio, and 30 FPS usability.

### Hour 10–11 — Submission and deployment

- Deploy production candidate to Vercel or Netlify.
- Verify clean-session URL, route refresh, headers, source links, licenses.
- Capture screenshots and a short demo recording only if submission requires it.
- Finish project description, NASA data explanation, team roles, open-source link, and AI-assistance summary.

### Hour 11–12 — Freeze and contingency

- Fix only release blockers.
- Re-run critical path and source/rights audit.
- Tag release and preserve deployed artifact.
- Submit before the deadline; verify the project page from a logged-out view where possible.
- Keep a second static-host deployment ready if the primary host fails.

## Member workload guardrails

- M1 does not become the default copy editor for unsourced content; M4 owns evidence.
- M2 does not author encounters while integrations are pending.
- M3 does not create mission-specific engine forks.
- M4 writes concise records first; Deep Dive expansion is lower priority.
- M5 optimizes/reuses before inventing new animation.
- M6 can block release for critical accessibility, privacy, rights, or data-loss failures.

## Fallback ladder

1. Remove decorative particles, transitions, and camera effects.
2. Reduce music/SFX variety while retaining controls and captions/transcripts where needed.
3. Shorten Deep Dives while preserving mission purpose, evidence, conclusion, uncertainty, and source.
4. Reduce nonfeatured catalog from 30 toward 25 entries.
5. Replace complex visual interactions with the accessible discrete-choice variant.
6. Preserve nine encounter beginnings/results even if some share more visible template structure.

Do not cut sources, rights checks, policy pages, keyboard/touch access, save controls, or campaign ending.
